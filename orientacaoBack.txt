# NEXO - GUIA DE ORIENTAÇÃO DO BACK-END

## 📂 1. Estrutura de Arquivos (/backend)

backend/
├── src/
│   ├── config/        # Conexões com serviços (supabase.js, etc.)
│   ├── controllers/   # Regras de requisição HTTP e respostas
│   ├── models/        # Manipulação e schemas do banco de dados
│   ├── routes/        # Mapeamento dos endpoints (/api/users/register, etc.)
│   ├── middlewares/   # Proteção de rotas (validação JWT, role e plan)
│   └── services/      # Regras de negócio complexas (integração IA Gemini)
├── .env               # Variáveis de ambiente (SUPABASE_URL, GEMINI_API_KEY)
├── .env.example       # Exemplo sem chaves reais
└── app.js             # Servidor principal Express

## 🌿 3. Orientações de Git Workflow

1. Trabalhar exclusivamente na branch local: `feature/api-usuarios`
2. Manter a branch `develop` intocada durante a codificação.
3. Após finalizar e testar o fluxo de usuários/login, subir as alterações:
   git push origin feature/api-usuarios
4. Abrir o Pull Request (PR) no GitHub direcionado para a branch `develop`.
